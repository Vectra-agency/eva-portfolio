# Eva Rovenskaia — портфолио

Сайт-портфолио на Next.js в трёх языках (RU / EN / KO) со встроенным редактором по адресу `/admin-editor`.

- `/` — перенаправляет на нужный язык: сохранённый выбор посетителя → посетитель из Кореи → язык браузера → английский.
- `/ru`, `/en`, `/ko` — главная; `/{язык}/certificates` — архив сертификатов по темам.
- `/admin-editor` — редактор (пароль задаётся переменной `ADMIN_PASSWORD`).

## Дизайны

В панели редактора (кнопки «Дизайн») можно выбрать один из трёх вариантов — выбор публикуется вместе с остальными правками:

- **Минимал** (по умолчанию) — белый фон, системный шрифт, одна колонка в рамке, как в исходном макете;
- **Журнал** — тёплая «бумага», антиква, редакционная вёрстка с анимацией;
- **Студия** — тёмный: огромное приветствие с градиентом, «живой» портрет (фото можно тянуть мышкой — оно тянется как тесто и пружинит обратно), лента из обложек и сертификатов, разделы-листы со скруглёнными углами. Для портрета лучше всего подходит PNG с прозрачным фоном; пока фото нет, тянется монограмма.

Разметка у всех дизайнов общая (`src/components/site`), отличаются стили: `src/styles/site.css` (журнал), `minimal.css`, `studio.css`. Текущий дизайн хранится в поле `design` файла `content/content.json`.

## Как устроено хранение

Весь контент лежит в репозитории:

- `content/content.json` — тексты на всех языках, ссылки, порядок пунктов;
- `public/uploads/` — фото, обложки, сертификаты и файлы для скачивания.

Vercel не умеет записывать файлы в работающий сайт, поэтому редактор сохраняет изменения коммитом в GitHub:

1. Правки в редакторе копятся как черновик (он хранится в браузере и переживает перезагрузку).
2. Загруженные файлы сразу отправляются в репозиторий как «объекты» git, но ещё не коммитятся.
3. Кнопка **«Опубликовать»** (или ⌘/Ctrl + S) делает один коммит: новый `content.json`, новые файлы и удаление файлов, которые больше нигде не используются.
4. Vercel видит коммит и пересобирает сайт — изменения появляются примерно через минуту.

Вся история правок видна в GitHub, любую публикацию можно откатить через `git revert`.

Ограничения:

- Один файл — до 4 МБ (лимит запроса на Vercel). Картинки сжимаются в браузере автоматически, поэтому ограничение касается только PDF/DOCX. Для больших файлов в редакторе есть поле «или внешняя ссылка» (Google Drive, Dropbox).
- ZIP «Архив сертификатов» не нужно загружать: он собирается в браузере посетителя из всех сертификатов на сайте.

## Деплой на Vercel

1. **Импорт проекта.** Vercel → Add New → Project → выбрать репозиторий. Настройки сборки менять не нужно.

   > На бесплатном тарифе Hobby Vercel не деплоит **приватные** репозитории, принадлежащие GitHub-организации. Варианты: сделать репозиторий публичным (секретов в нём нет — пароль и токен хранятся только в Vercel), перенести его в личный аккаунт или перейти на Pro.

2. **Токен GitHub.** GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token:
   - Resource owner: организация, в которой лежит репозиторий;
   - Repository access: Only select repositories → этот репозиторий;
   - Permissions → Repository → **Contents: Read and write**;
   - срок действия — на ваше усмотрение (когда токен истечёт, публикация перестанет работать — нужно выпустить новый и заменить его в Vercel).

   Если организация требует одобрения токенов, одобрите его в настройках организации (Settings → Personal access tokens → Pending requests).

3. **Переменные окружения** (Vercel → Project → Settings → Environment Variables, окружение Production):

   | Переменная       | Значение                                              |
   | ---------------- | ----------------------------------------------------- |
   | `ADMIN_PASSWORD` | пароль от `/admin-editor`                             |
   | `GITHUB_TOKEN`   | токен из шага 2                                       |
   | `GITHUB_REPO`    | `владелец/репозиторий`, например `Vectra-agency/eva-portfolio` |
   | `GITHUB_BRANCH`  | ветка, из которой деплоит Vercel (по умолчанию `main`) |
   | `SESSION_SECRET` | необязательно: любая длинная случайная строка          |

4. **Redeploy**, чтобы переменные подхватились. Затем откройте `https://<домен>/admin-editor`.

## Локальная разработка

```bash
npm install
cp .env.example .env.local   # впишите ADMIN_PASSWORD
npm run dev
```

Без `GITHUB_TOKEN` редактор работает в локальном режиме: «Опубликовать» пишет прямо в `content/content.json` и `public/uploads/`, а коммит вы делаете сами. Если задать `GITHUB_TOKEN` и `GITHUB_REPO`, локальный редактор будет коммитить в GitHub так же, как на продакшене.

## Структура

```
content/content.json          контент сайта
public/uploads/               загруженные файлы (управляются редактором — лишние удаляются при публикации)
src/app/[locale]/             страницы сайта
src/app/admin-editor/         редактор
src/app/api/admin/            вход, загрузка файлов, публикация
src/components/site/          секции сайта (одни и те же компоненты и на сайте, и в редакторе)
src/components/edit/          редактируемые тексты, картинки, кнопки списков
src/lib/server/               авторизация, работа с GitHub и файлами
src/proxy.ts                  выбор языка для «/»
```
